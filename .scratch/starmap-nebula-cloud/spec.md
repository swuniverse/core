# Rasterunabhängige Nebelhülle

Reine Darstellung vorhandener filmischer Galaxienebel im Workspace codex/starmap-nebula: kontinuierliche Wolkenoberfläche und schwacher Gasschleier bis etwa ein Feld außerhalb tatsächlicher Nebelfelder, größere Randbewegungen. Feldtypen, Kosten, Schaden, Seed-Metadaten und Generatorausgabe bleiben erhalten. Kein Regenerieren oder Anwenden von Terrain.

Shared: NebulaCloudSource {x,y,visual}; buildNebulaCloudIndex(sources) indexiert ausschließlich bekannte aktive Quellen. renderNebulaCloudField(index,x,y) liefert eine kontinuierlich maskierte 30×30-RGBA-Textur oder undefined. Gaussian-Fläche aus benachbarten Quellen, breite Weltkoordinaten-Verformung, dieselbe filmische Detailtextur. Keine feldweise Konturmaske mehr. isNebulaCloudSpace(type) kennzeichnet zulässige Weltraum-Haloempfänger; unbekannte und anderweitige Terrainfelder ausgeschlossen. Quellen aus maximal 2-Feld-Nachbarschaft, begrenzte Raster-/Textur-Caches. Smooth-Abfall statt unterschiedlicher feldabhängiger Alpha-Caps, um neue Rasterkanten zu vermeiden.

Backend: Spieler erhalten nur PNG-Ausschnitte bekannter Empfänger und bekannte Nebelquellen beeinflussen diese. Keine Seeds/Descriptor-Daten für Spieler. Quellenkontext vor DTO-Redaktion nur aus persönlich bekannten/erkundeten Feldern (oder explizitem Admin-Fog-Bypass) bilden; LSS aus nicht redigierten Sensorfeldern. Sektorabfragen holen einen 2-Feld-Puffer für Quellen und Aufklärung, geben weiterhin nur angeforderten Sektor zurück. Cache-Schlüssel enthält sichtbare Quellen inklusive ihrer visuellen Beschreibung; wechselnde Kenntnis darf keine alten Halos übernehmen.

Frontend: lib/nebula-cloud.ts exportiert getNebulaCloudDomStyle(index,x,y); lib/nebula-cloud-pixi.ts exportiert getNebulaCloudPixiTexture(index,x,y). Drei Galaxieansichten und Editor-Vorschau bilden einen sichtbaren Quellenindex (useMemo bzw. pro Renderpass). Quelle nur bei active nebulaVisual und Nebel-Feldtyp, niemals UNKNOWN/redacted. NebulaTexture aus Backend ist bereits komplett maskiert, keine organic/legacy Maske auf diese anwenden. Descriptor-Clouds ebenfalls ohne Feldmaske. Legacy-Terrain erhält alte Darstellung. Bekannte Weltraumfelder ohne eigenes nebulaVisual können getNebulaCloud* verwenden; andere Terrainarten nicht. Sterne/Systeme/Routen bleiben darüber sichtbar. Preview-Quellen aus finalen Änderungen/restores/current descriptors.

Tests: weiche Fläche über Nebelfeldgrenzen, Fransen und große Randbewegung, Halo auf bekanntem EMPTY_SPACE, keine Quelle aus UNKNOWN/redacted, cache privacy, gleiche Rasterpixel bei unterschiedlichen Anfragen einschließlich Sektor-Puffer; keine Feld-/Kostenänderungen. Typecheck, betroffene Integration, App-Builds, gesammelte Suites, laufende API und PNG-Vergleich.
